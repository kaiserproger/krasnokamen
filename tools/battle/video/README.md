# Battle telemetry overlay and composition

Python 3 standard library, ffmpeg with libx264, drawtext, xfade and AAC, and DejaVu Sans Bold at `/usr/share/fonts/truetype/dejavu/DejaVuSans-Bold.ttf` are required. No wall-clock is read. Inputs are the E1 `/telemetry.jsonl` export and C3 `shot.frames.jsonl`. The E1 export is produced by the battle runner `tools/battle/run-battle.py`, which is not in this tree (it lives on the pre-rename battle line); in this tree only `synthetic.py` generates a sample `telemetry.jsonl` for tests. One PNG per C3 frame, at 60 fps; exact tick join uses `last_applied_tick` (the last shutter sample when motion blur is enabled). Missing tick fails instead of inventing telemetry. Output directory must not exist.

```sh
# N shots of a shots.txt (NAME.mp4 + NAME.frames.jsonl per shot from bv-render), tick map, overlay and encode in one go:
python3 tools/battle/video/compose.py build --shots-file /work/shots.txt --first-tick 2279 --frames-dir /work/shots --shots-dir /work/shots --telemetry /work/telemetry.jsonl --work /work/montage --title-file /work/title.txt --crossfade-frames 12 --resolution 1080p --output /work/final.mp4
# Only the output-frame tick map (edit.frames.jsonl); without --frames-dir the ticks are predicted from shots.txt:
python3 tools/battle/video/compose.py map --shots-file /work/shots.txt --first-tick 2279 --frames-dir /work/shots --out /work/edit.frames.jsonl
# Overlay PNGs for any frames map:
python3 tools/battle/video/overlay.py --telemetry /work/telemetry.jsonl --frames /work/edit.frames.jsonl --out /work/overlay
# Stand-in shots (preview stills held per shot, tick burned in) for a dry run:
python3 tools/battle/video/standins.py --shots-file /work/shots.txt --first-tick 2279 --previews /work/previews --out /work/standins
```

Shots are used in shots.txt order, each with its own `NAME.frames.jsonl`: the tick of every output frame is that file's `last_applied_tick`, so the overlay shows the telemetry of the tick the frame shows. `build` fails if a shot MP4's frame count differs from its frames file, if a shot's first tick is not `first_tick + round(START*20)` (+-1: wrong take), or if a tick is missing from the telemetry. `--crossfade-frames K` (default 0 = hard cut) overlaps the tail of each shot with the head of the next by K frames; in the overlap each output frame takes the tick of exactly one shot, the outgoing one for the first K//2 frames and the incoming one after, and every shot must be longer than 2K frames. `--music` is optional (looped, loudness-normalized, use only licensed audio); without it the MP4 has no audio track. The title file is literal UTF-8, shown during the first three seconds; picture fades in over 0.5 s and out over 1 s (the panel is not faded). Use `--resolution 4k` for 3840x2160 (shot MP4s are scaled to the target; render them at that size on the laptop to gain detail). Encode: H.264 High with 2 B frames, closed 30-frame GOP, CRF 16, AAC 384k/48 kHz, BT.709 limited-range tags and faststart. Output directory `--work` and output file must not exist. During a crossfade two source times are visible; the panel describes only the tick named in the edit map.

Graph: 180 tick history; green = full active `wall_us` MSPT on a fixed 0–100 ms scale, clipped at 100; amber 50 ms budget line; blue = instantaneous TPS on a 0–20 TPS scale, clipped at 20 (numeric TPS remains unclipped). Missing ticks create line gaps. Numeric cgroup CPU is percent of one CPU (may exceed 100), derived from consecutive host-sample `usage_usec` and sampled timestamp; steal from proc-stat deltas, memory is cgroup bytes in GiB. Host values are held from the last sampled tick; unavailable counters are `N/A`, not zero. `battle.units` is the number of faction rows, not the number alive; `battle.alive` supplies per-faction living counts. Faction IDs are read from the map, ordered numerically; absent battle data displays `N/A`, and more than two factions is rejected. Metrics are not synthesized from footage.

No-backtrack edit (`--no-backtrack`, needs `--frames-dir`): shots are ordered by START; where a shot's first tick is earlier than the tick after the previous kept shot's last frame, its head is trimmed (`trim` filter on the already rendered MP4, from its frames.jsonl tick map) so battle time never steps back at a cut. A shot left with fewer than `--min-shot-seconds` (2) is dropped. A cut is exempt (the backtrack stays) when the angle changes sharply: the horizontal look direction turns by `--sharp-yaw` degrees (default 60) or the camera positions or look targets are more than `--sharp-distance` blocks (default 40) apart (the rule of tools/battle_shots.py check; entity-attached cameras: heading only), between the previous shot's last camera key and the next shot's first. `build` prints and stores `cut-table.md`/`cut-table.json` in `--work` (in/out tick, delta vs previous, original delta, trimmed frames, exception, status).

Live clips (shots.txt camera field `live`, MP4 `NAME.mp4` in `--shots-dir`, `NAME.ffmpeg.log` + `NAME.anchors.json` in `--frames-dir`, `--telemetry` needed): the clip is a laptop x11grab recording whose frames have no tick. `live.py` maps each frame to a tick through the recorder's wall clock (showinfo lines of a `-use_wallclock_as_timestamps 1 -copyts` recording), a measured host-minus-laptop clock offset (`live.py clock`, before and after the take, linear in between, no extrapolation) and at least one visible marker (event, server tick, captured frame) that must agree with the clock map within 6 ticks (two markers: within 2 ticks of each other); the median marker shift is applied. START/END are take seconds and select the excerpt by tick. A clip with no marker, a disagreeing marker or telemetry that does not cover it is UNANCHORED: the whole clip is used (START/END only order it), the panel shows `NO TELEMETRY / UNANCHORED LIVE` and no graph. A cut involving a live clip counts as a sharp angle change. `live.py predict` names the captured frame where a tick should show, `live.py anchors` writes `NAME.anchors.json`. `compose.py` resamples every input to 60 fps before trimming, so frame numbers are on that grid.

Several excerpts of one recording: shot names are unique, so give each excerpt its own alias NAME (`NAME.mp4`, `NAME.ffmpeg.log`, `NAME.anchors.json` may be symlinks/copies of the recording's files); the frame count and tick grid of a recording are computed once. A recorder may outlive the take: frames the telemetry does not cover get no tick, and only an excerpt that contains one is refused. `build --panel-label "LIVE SERVER TELEMETRY"` changes the panel header after the tick (default `REPLAY TELEMETRY`; the telemetry of a live run is not a replay), `--units-label "SOLDIERS + HORSES"` makes the UNITS line say what it counts (telemetry `units` includes horses) and moves the sides to a second line (panel 20 px taller), `--caption-file FILE` draws a persistent bottom-left caption, one stacked box per line of the file (what the footage is: live clients or render replay, soldier count).

Run focused tests: `cd tools/battle/video && python3 test_overlay.py && python3 test_compose.py && python3 test_live.py`. A failed or interrupted render can leave partial output; use a new output path for each attempt. The sample synthetic render in the receipt is not a battle or proof of live server performance.
