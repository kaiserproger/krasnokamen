# Solaris 1.0 "Pauline" RC4

RC4 targets Minecraft Java Edition 26.3, with 26.1.2 protocol support as in
[RC3](https://github.com/kaiserproger/solaris/releases/tag/v1.0.0-rc.3).

## Changes

- Fixes for crafting inventory transfers, wall placement, sheep and goat
  presentation, and several other owner playtest findings.
- Settlement map and storage interface improvements, along with automatic
  crafting of dependency chains.
- Client rendering corrections for camera poles, directional block shading,
  poplar boats, giants, bee anger and decorated-pot patterns. Zombie-family
  mobs hold their arms forward, goat horns are spaced like vanilla, spiders get
  a walk cycle, and a held tool no longer pokes into a wall you stand against.
  These need the matching client build; full vanilla visual parity is not claimed.
- Screenshots from the opaque client surface no longer contain unintended
  transparent pixels from the framebuffer.
- Container block-entity privacy fixes for the container types exercised so far.
  Decorated pots intentionally withhold contents and unopened loot from clients,
  unlike vanilla; comprehensive coverage of all block entities is not established.
- Armadillo scute shedding now advances its countdown in game ticks rather
  than once per ten-tick threat check.
- Grounded entities with levitation are no longer incorrectly classified as
  resting on the tick when the effect is applied.
- Closing an inventory with an item on the cursor now clears the client cursor
  after returning the item, preventing a stale phantom stack on reopening.
- A pending block edit under a resting mob now wakes its physics before the
  edited chunk is folded, so support removal is observed on that tick.
- Rejoining from the Nether or the End keeps the player's client language.
- A player with a full inventory no longer starves item pickup for others
  standing next to the same item.
- Brushable blocks no longer send their loot table and seed to clients.
- Emptying a bucket onto a cobweb or similar block pops it like vanilla,
  without wearing your tool or counting it as mined.
- Kelp grows into flowing and falling water, both naturally and with bone meal,
  so poured water columns and bubble elevators can be planted like vanilla.
- A restarted server opens its port only after it is ready to serve, so a
  reconnecting client no longer times out while the server is still starting.
- Portal checks for entities in unloaded chunks skip the serial path. In a
  synthetic test with a million entities this phase took 11.4 ms instead of
  45.7 ms. No server TPS gain is claimed.
- Bug status now lives in `docs/bugs/ledger.toml`. `python3 -m tools.harness run
  regressions` reruns every Cargo check recorded there (79 at release) and runs in
  CI; real-client checks run separately via `regressions-client`. Old bugs are
  protected only where a check is recorded.

## Upgrade

For upgrades from RC1, see the content import and world-generation upgrade steps
in the [RC2 notes](https://github.com/kaiserproger/solaris/releases/tag/v1.0.0-rc.2).
Upgrading an RC3 world and a clean install from the packaged launcher were not
tested for RC4.

## Validation and known limitations

Core: full L2 correctness (fmt, strict clippy, code-health, 6,959 tests) passed on
the release Rust sources; the later test- and ledger-only changes were followed by
a passing `regressions` run. An independent breaker re-attacked the release server
with the release client: restart with six reconnects in a row, town permissions,
settlement storage and pickup with a full inventory all held. Native client:
workspace tests and a windowed survival run (join, mine, pick up, place) pass
against the release server. Client strict Clippy still reports existing
warnings.
Cushion and sulfur-cube models are not included in this client build; those
entities use the fallback model until re-authored.
Industrial settlement delivery and full visual model coverage are not proven.
The million-entity research runs are not an RC4 capacity claim.
