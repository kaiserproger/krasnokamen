# Solaris 1.0 "Pauline" RC4

RC4 targets Minecraft Java Edition 26.3. As in
[RC3](https://github.com/kaiserproger/solaris/releases/tag/v1.0.0-rc.3), 26.1.2
clients (protocol 775) can join only while the server has a separate, intact
26.1.2 content cache; without it they are refused. The normal content import
cannot recreate that cache, so keep the existing one before importing 26.3: see
[Retaining 26.1.2 clients after upgrading to 26.3](https://github.com/kaiserproger/solaris/blob/v1.0.0-rc.4/docs/OPERATING.md#retaining-2612-clients-after-upgrading-to-263).

## Changes

- Fixes for crafting inventory transfers, wall placement, sheep and goat
  presentation, and several other owner playtest findings.
- Settlement map and storage interface improvements, along with automatic
  crafting of dependency chains.
- Client rendering corrections for camera poles, directional block shading,
  poplar boats, giants, bee anger and decorated-pot patterns. Zombie-family
  mobs hold their arms forward, goat horns are spaced like vanilla, spiders get
  a walk cycle, and a held tool no longer pokes into a wall you stand against.
  These need the matching client build; full vanilla visual parity is not claimed.
- Screenshots from the opaque client surface no longer contain unintended
  transparent pixels from the framebuffer.
- Container block-entity privacy fixes for the container types exercised so far.
  Decorated pots intentionally withhold contents and unopened loot from clients,
  unlike vanilla; comprehensive coverage of all block entities is not established.
- Armadillo scute shedding counts its timer in game ticks: the countdown drops
  by ten at each ten-tick threat check.
- Grounded entities with levitation are no longer incorrectly classified as
  resting on the tick when the effect is applied.
- Closing an inventory with an item on the cursor now clears the client cursor
  after returning the item, preventing a stale phantom stack on reopening.
- A pending block edit under a resting mob now wakes its physics before the
  edited chunk is folded, so support removal is observed on that tick.
- Rejoining from the Nether or the End keeps the player's client language.
- A player with a full inventory no longer starves item pickup for others
  standing next to the same item.
- Brushable blocks no longer send their loot table and seed to clients.
- Emptying a bucket onto a cobweb or similar block pops it like vanilla,
  without wearing your tool or counting it as mined.
- Kelp grows into flowing and falling water, both naturally and with bone meal,
  so poured water columns and bubble elevators can be planted like vanilla.
- A restarted server opens its port only after the edge has finished starting;
  before, the port opened about ten seconds early. Reconnect timeouts seen in
  testing stopped after this change, but that cause was not proven.
- Portal checks for entities in unloaded chunks skip the serial path. In a
  synthetic test with a million entities this phase took 11.4 ms instead of
  45.7 ms. No server TPS gain is claimed.
- Bug status now lives in `docs/bugs/ledger.toml`. `python3 -m tools.harness run
  regressions` reruns every Cargo check recorded there (79 at release) and runs in
  CI; real-client checks run separately via `regressions-client`. Old bugs are
  protected only where a check is recorded.

## Upgrade

For upgrades from RC1, see the content import and world-generation upgrade steps
in the [RC2 notes](https://github.com/kaiserproger/solaris/releases/tag/v1.0.0-rc.2).
An RC3 world with placed blocks, a stocked chest and a settlement reopened in RC4
with its state intact. This was tested on one seed after a clean shutdown.

## Validation and known limitations

Core: full L2 correctness (fmt, strict clippy, code-health, 6,959 tests) passed on
the release Rust sources; the later test- and ledger-only changes were followed by
a passing `regressions` run. An independent breaker re-attacked the release server.
With native client commit `cbe9a327`, restart with six reconnects in a row,
settlement storage, and a contested pickup with one free slot all held; town
permissions held with a Java client.
The same breaker ran three clean installs of the Linux package built from client
`2e9f336` (`cbe9a327` plus release pins, same client binary) with fresh profiles:
each downloaded content, entered singleplayer, saved and rejoined, with the
launcher running headless. It also ran Loader settlement smokes
once each on Fabric and Forge. A NeoForge smoke, run separately from the breaker,
passed once after the Loader build fix. The breaker did not complete its full
attack matrix for this release, including negative controls. Client strict
Clippy still reports existing warnings.

The final client, `5d34e88`, adds a resource-path change that runs on every
platform but only alters resource ids where the system path separator is a
backslash, a network change whose behavior differs only on Windows, and the
release pins. On
Linux it passed a title-screen connect test against the release server; the
breaker's runs above were not repeated on it.

Windows: the native client package now bundles its runtime (the RC3 package
needed the Visual C++ runtime); in a Windows 11 VM it started with a new profile.
RC4 fixes
resource paths that stopped the Windows client before the title screen. It also
stops polling the game connection with short receive timeouts, the likely cause
of a multiplayer disconnect after a few minutes ("os error 997"). In a Windows
VM, three multiplayer sessions with a locally built package stayed connected for
23 to 26 minutes. Two of them started from a fresh profile and a fresh world; the
first reused an earlier profile and an already played server world.
The same test with the client from before this change disconnected with error
997 after four and a half minutes. These runs cover the multiplayer connection
only. In a locally built package,
Microsoft Defender flagged the singleplayer launcher with a generic
machine-learning verdict (Bearfoos.B!ml) and blocked singleplayer, so Windows
singleplayer is not verified. macOS packages were not exercised before tagging.
The native client disconnects from servers that offer a resource pack; vanilla
clients are unaffected.
Cushion and sulfur-cube models are not included in this client build; those
entities use the fallback model until re-authored.
Industrial settlement delivery and full visual model coverage are not proven.
The million-entity research runs are not an RC4 capacity claim.
